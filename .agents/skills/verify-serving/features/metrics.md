# Framework metrics and correctness preflight

The maintained adapters are `tools/benchmark_serving.py` and `tools/locustfile.py`. Handwritten experimental study drafts are archived under ignored `evidence/custom-metrics-draft/` and must not be used as accepted benchmarks.

Use an isolated project `.metrics-venv` that exposes the existing pinned ML site-packages read-only. Install only `requirements-metrics.lock` with `--no-deps --require-hashes`; this lock covers Windows CPython 3.11 extra wheels. Preserve the base versions in `constraints-metrics.txt` and require `pip check`. Never reinstall Torch, Transformers or model weights in the shared runtime. Locust 2.47.0 is MIT licensed. Its [official client documentation](https://docs.locust.io/en/stable/writing-a-locustfile.html) describes the HttpUser request/statistics boundary.

Run `python tools/benchmark_serving.py --model <cached-Qwen-directory> --output evidence/<fresh-id> --preflight` only with an exclusive resource grant. The latest SDPA preflight and 128/32/concurrency-4 shard passed at `evidence/hf-sdpa-{preflight,full}-20261022-0746/`. A second measured 256/64/concurrency-1 case passed at `evidence/hf-sdpa-i256-o64-c1-20261022-105338/`. Curated exact result, oracle and supervisor receipts for both are under `docs/evidence/torch-metrics-20261022/`; the summary reports two of 24 proposed offline cells. Preserve earlier receipts: original paged preflight; 0716 private-helper API failure; 0719 native-HF-eager preflight; 0721 prelaunch disk-guard failure; and 0737 native-HF-eager historical control with separate graph profile. The eager control used a different HF attention backend and supports no tuned-native-HF comparison claim.

The frozen comparison has **three arms**: native Transformers `generate`, portable paged eager, and paged graph decode. All use the same pinned BF16 weights, Torch SDPA primitive, token-ID prompts, exact output count and maximum live batch. The independent oracle remains single-request eager full-forward greedy; its exact token file is byte-identical to the prior control. The same HF model switches to SDPA through public `set_attn_implementation` after oracle construction, with a config assertion; no fourth copy is loaded. CUDA dispatch can select different SDPA kernels for the APIs' tensor/mask layouts. Per-arm backend and profile scope are recorded explicitly. Full mode uses 16 prompts; measured cells are `--input-length 128 --output-length 32 --concurrency 4` and `--input-length 256 --output-length 64 --concurrency 1`. Preflight uses two 16-token prompts, two output tokens and concurrency two.

Native HF uses contiguous batches no larger than concurrency and a fresh native DynamicCache per batch. Paged engines use `max_num_batched_tokens = concurrency * input_length`, matching full-batch prefill capacity; this is a frozen workload configuration, not a source optimizer result. Every paged invocation replaces an inactive scheduler to prevent reuse, including both automatic Timer warmups. Prompts have distinct first tokens; measured page receipts must show zero prefix hits and zero active references. Weights/graphs stay warm. HF and paged arms both decode returned token lists to text and check every final token against independent single-request full-forward greedy results. Model loading/oracle construction are excluded; paged scheduler reset, native input transfer, text decoding and correctness checks are included.

HF generation starts from neutral framework defaults and passes `do_sample=False`, one beam, `max_new_tokens=min_new_tokens=count`, explicit `eos_token_id=None` and `forced_eos_token_id=None`. This disables EOS stopping while preserving EOS as a possible greedy token. In installed Transformers 5.20.2, `_prepare_generation_config` applies explicit kwargs after pretrained defaults; minimum-length EOS suppression is only added when `_eos_token_tensor` is present. Before any timing the adapter audits effective native configuration, requiring no logits processors and only `MaxLengthCriteria`. The private audit calls are version-specific and must fail visibly on API drift; native `generate` owns actual decoding.

Every arm uses Torch Timer `timeit(number=1)`, including two framework warmups and CUDA synchronization. Five repeats rotate arm order, with each arm appearing in each position and no position used more than twice. Preflight has one trial per arm and supports no performance claim. All three models stay resident to permit fair interleaving; receipts distinguish total resident/peak CUDA allocation, incremental arm peak, native dynamic-cache bytes and paged pool/scratch bytes. A 16 GiB allocation cap and 10 GiB free-disk reserve are checked. Require an external owned-process timeout: 600 seconds for preflight and the 128/32/4 shard, 1,800 seconds for the 256/64/1 long case. The separate 0737 graph-arm Torch profile is excluded from Timer samples and reused only because its paged source/config and full oracle are unchanged. It contains four prefill and 124 decode calls. Its overlapping CUDA annotation percentages exceed 100%; do not add them or infer wall-time shares. It is not a baseline-arm profile and does not establish causal attribution of the timing differences. Source/model hashes and exact calls accompany the result.

For HTTP, start only an owned loopback server. Set `SERVING_ORACLE` to the preflight's `oracle.json` and `SERVING_COUNTS` to a fresh evidence path. Run `python -m locust -f tools/locustfile.py --headless --users 2 --spawn-rate 2 --run-time 8s --stop-timeout 30 --host http://127.0.0.1:<owned-port> --csv evidence/<fresh-prefix>`. Locust owns scheduling and latency distributions; the adapter parses the product's custom top-level SSE events, checks every final token list and reports TTFT/ITL separately. Its completion timing includes body consumption. Counts distinguish completed, rejected, failed and client-aborted tasks at shutdown. The final real smoke had `226 = 224 completed + 2 client-aborted`; server metrics showed 224 accepted/completed and zero live requests/pages. These counts prove adapter behavior only.

Locust is closed loop. Its aggregate row mixes completion and custom token events and must not be labeled request throughput. Use the `POST completion` row and owned counts. It cannot establish open-loop offered-rate tail behavior; add a standard constant-arrival load stage before making that claim. Retain the original `evidence/locust-preflight.log` and 211/209 failed accounting receipt, plus `locust-preflight2*` successful receipts. Cleanup must stop only the recorded server and verify no owned CUDA process remains.

The broader offline matrix in `docs/torch-metrics-plan.md` has two measured cells and 22 unrun cells. It reuses this same adapter over 24 input/output/concurrency cases, with explicit per-process resource caps. Each additional run requires a serialized resource grant. Do not infer 7B behavior, TTFT, live service capacity or language quality from these offline measurements, and do not name a causal winner from timing alone.
